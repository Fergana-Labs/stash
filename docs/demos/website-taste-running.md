# Run the website-taste experiment

The intended learned-grader path is now the separate
[frozen-model activation probe](website-taste-activation-probe.md). Its first
cloud run completed, but failed quality checks and a confirmed human
counterexample. Optimization remains blocked. The older classifier and Claude
investigator below remain available for comparison and audits.

This operator harness prepares a real, private history dataset and runs the
[four-arm experiment](website-taste-experiment.md). It is separate from the
synthetic website-design fixture. It does not import all traces into Stash,
execute commands from old transcripts, or load Qwen weights locally.

Run from the consolidated checkout. Install
`scripts/website_taste/requirements.txt` in a small tools environment. Keep all
outputs outside the repository. Set `STASH_URL`, `STASH_API_KEY`, and
`ANTHROPIC_API_KEY` for the intended account/environment. The local demo uses
the API at `http://127.0.0.1:3495` and frontend at `http://localhost:3457`.
Never copy account keys into datasets, reports, commits, or command output.

## Prepare and review

```sh
python -m scripts.website_taste discover --output /private/tmp/website-taste
python -m scripts.website_taste recover --output /private/tmp/website-taste
python -m scripts.website_taste extract --output /private/tmp/website-taste --model claude-haiku-4-5
python -m scripts.website_taste calibrate --output /private/tmp/website-taste
python -m scripts.website_taste prepare-test --output /private/tmp/website-taste --model claude-sonnet-4-6
```

Discovery records scan coverage, oversized/malformed rows, candidate sessions,
and unresolved resumed-history limitations. Matches are candidates, not labels.
Recovery saves embedded user screenshots and narrowly parsed, complete recorded
HTML writes with success receipts. It never substitutes the current working
tree for historical source. Files outside Codex's history roots and symlinks are
not used as transcript sources. Resumed pages are not expanded by this operator
scanner; the product history connector remains available for that investigation.

Preference extraction returns exact quotes and source/image references. Wrong
quotes abstain; malformed reference mappings get one retry and then abstain.
Positive comments about one aspect or a game/task run do not become approval of
the whole design. All proposed labels remain pending review.

`calibration.json` contains the native wizard links. Open them in the selected
account to confirm/change labels; images can be enlarged. The classifier's final
test examples use a separate review-only eval container so they never become
classifier references. The six fresh designs are generated by Claude solely for
calibration: two development examples and four untouched final-test examples.
Their labels are unknown until reviewed; they are not
Qwen outputs, post-training results, or implicitly liked/disliked fixtures.

The user does not export, upload, or import history manually. These commands are
operator work; the user's interaction is the normal image-labeling step.

### Explicitly authorized automatic-label pilot

If Henry asks to skip manual labeling, use a **separate** exploratory directory:

```sh
python -m scripts.website_taste auto-label --source /private/tmp/website-taste --output /private/tmp/website-taste-auto --model claude-sonnet-4-6
python -m scripts.website_taste freeze --output /private/tmp/website-taste-auto --automatic-exploratory
```

The visual teacher rechecks each screenshot against the full source message and
image index, corrects desired-reference attribution, and abstains on functional
requests or uncertain feedback. Every accepted history label needs an exact
human quote. Fresh dev/test designs get teacher-inferred labels from a profile
derived from training messages only, without seeing their generation prompts.
All receipts retain `human_reviewed: false`; the original manual queues remain
pending. Separate eval containers accept automatic labels for this experiment.
The normal human-reviewed protocol still rejects these labels.

This mode measures agreement with automatic labels, **not human-validated
accuracy**. Its exploratory cloud gate requires at least four teacher-labeled
held-out examples, both labels in each partition, the ordinary release gate,
and at least 75% agreement. The threshold is fixed before fitting. There is no
independent validation of personal taste until Henry judges unseen outputs.
Keep the approved cloud budget across both directories; a new directory does
not authorize a new budget. Select the authorized Modal workspace explicitly
with `MODAL_PROFILE=fergana-labs` for this pilot's cloud commands.

## Freeze and fit

```sh
python -m scripts.website_taste sync-reviews --output /private/tmp/website-taste
python -m scripts.website_taste freeze --output /private/tmp/website-taste
python -m scripts.website_taste fit --output /private/tmp/website-taste --reflection-model claude-sonnet-4-6
python -m scripts.website_taste skill --output /private/tmp/website-taste --reflection-model claude-sonnet-4-6
```

Related Stash worktrees, sessions, and duplicate pixels stay together. The
largest evidence group stays in training; two independent groups are reserved
for development and final testing. Fresh calibration designs add development and
final-test examples. Every partition needs both reviewed labels. Freezing
hashes the exact examples, tasks, model revision, system prompt, and limits;
changes require a separate experiment.

Criteria and the baseline skill use training evidence only. The skill gets a
draft, critique, and revision using the training screenshots' visual descriptions
and actual feedback. GEPA starts from this same baseline, not a deliberately
weak seed. The current classifier method is rubric/verdict features plus a
calibrated head; this does not claim to implement an unconfirmed newer NSP method.

The existing classifier release gate and the personal-taste development checks must pass: at least four development examples, at least two per label, at least 75% agreement, and at least 50% recall for each label. A general release gate can otherwise pass without enough development observations. A separate pilot gate requires
at least six untouched, human-labeled classifier-test examples and at least 75%
agreement before GPU optimization can run. This is a small pilot threshold, not
a claim that the classifier is generally accurate. A failed test does not
authorize repeated tuning on that test set; prepare a new experiment and fresh
test data for a new claim.

## Review and approve the cloud job

```sh
python -m scripts.website_taste plan --output /private/tmp/website-taste
```

Review `cloud-plan.json` with Henry before launching larger compute, as required
by the repository's compute instruction. The first plan pins
`Qwen/Qwen3-8B` to revision
`b968826d9c46dd6066d109eabc6255188de91218`, with BF16 inference on Modal L4,
24 GEPA metric calls, and at most 72 total generation requests. Each request
permits 4,096 output tokens and has a ten-minute server timeout. Final inference
uses the same settings across arms.

Generator post-training is explicitly reward-labeled DPO with a rank-8 LoRA
adapter on Modal A100-80GB, 40 steps, and a 45-minute server timeout. The worker
also stops its optimization loop after 30 minutes and will not serve an adapter
unless every requested step completed. At least four independent training briefs
must produce valid, reward-separated chosen/rejected pairs. Those pair labels
come from the frozen classifier, not directly from Henry. No dev/test output
enters DPO.

The plan uses the official [Qwen model](https://huggingface.co/Qwen/Qwen3-8B) and
[Modal GPU runtimes](https://modal.com/docs/guide/gpu). Check
[Modal pricing](https://modal.com/pricing) when approving the job. A spending
budget requires operator monitoring; call/token/time limits are enforced by this
harness, but it is not a provider billing cap. No GPU training has been validated
merely by preparing this code or running CPU unit tests.

After approval and the data gates pass:

```sh
modal deploy scripts/website_taste/cloud.py
python -m scripts.website_taste optimize --output /private/tmp/website-taste --allow-cloud
python -m scripts.website_taste sample-dpo --output /private/tmp/website-taste --allow-cloud
python -m scripts.website_taste train-dpo --output /private/tmp/website-taste --allow-cloud
python -m scripts.website_taste evaluate --output /private/tmp/website-taste --allow-cloud --adapter ADAPTER_FROM_POSTTRAINING_RECEIPT
```

The Modal app creates private model/checkpoint volumes; importing the ordinary
preparation commands does not create them. Cloud generation receives the task
and learned instructions; DPO receives generated training pairs. Neither worker
receives the history corpus, Stash login, database credentials, or queue access.
The GPU worker rejects local execution before importing any ML packages.

Every trial retains its prompt identity, Qwen revision, HTML, PNG, usage, and
pinned prediction receipt. Provider errors abort rather than counting as bad
designs. Invalid HTML is recorded separately with zero valid-design utility.
Completed identical requests are cached; process restarts do not reset the
generation-call ledger. Reward changes cannot reuse the same GEPA run directory.

The baseline and GEPA arms keep Qwen weights fixed. The post-trained arm uses
the same ordinary skill as the skill-only arm to isolate the weight change.
GEPA and weight refinement are independent experiments, not pipeline stages. Weight refinement can run and be evaluated without any GEPA result. With an adapter, its inference uses the original baseline skill, never the GEPA skill. Evaluation includes only the arms whose artifacts exist.

## Judge the outcome

### Watch the run locally

```sh
python -m scripts.website_taste.gallery --output /private/tmp/website-taste-auto --port 3458 --worker-pid YOUR_OPERATOR_PROCESS_ID
```

Open `http://localhost:3458`. The design journal reads the live output folder,
refreshes automatically, and shows previews while they are being scored. It
includes chronological and score sorting, brief/method filters, keyboard image
navigation, exact skills and diffs, and a two-design comparison. It defaults to the research brief so the prompt stays fixed across attempts. Incomplete attempts remain visible. The independent GEPA and weight-refinement branches appear side by side. The worker PID is optional; without it,
the site watches outputs without claiming the underlying compute is active.

The server binds to loopback only. Its allowlisted endpoints serve experiment summaries, known PNG screenshots, exact per-trial instructions and baseline diffs, and saved agent-judge inspection reports. Those reports include the evaluated trace/source and the specific training preference quotes supplied to the judge. It does not expose the raw history corpus, credentials, or arbitrary files. Generated HTML is displayed as text and is never executed by the gallery. Completed designs that used unchanged seed
instructions are marked as the skill baseline even during GEPA search. DPO
sampling is distinct from post-trained inference. Invalid HTML is displayed as
invalid output, not as an aesthetic dislike. Retries of one request share one
saved-output card. The journal is a separate local site; it does not replace the
Stash app on port 3457 or deploy a public copy of private experiment outputs.


### Inspect the trace-and-render agent judge

The original automatic pilot was stopped after a human rejected its 92.5-scored
monitoring dashboard. Its development agreement was only 1/3; about 98% of
reported feature influence came from the generic verdict. That classifier's old
scores are preserved for diagnosis, not treated as valid rewards. The presence
of `pilot-invalidated.json` blocks all further GPU commands from that directory.
The cloud application and local pilot driver were stopped; no weight training ran.
A new judge must be validated in a separate experiment before optimization resumes.

The journal's **The judge** tab shows both the failed classifier and the new
exploratory agent evaluator. For a saved complete trial:

```sh
python -m scripts.website_taste.trace_judge --output /private/tmp/website-taste-auto --trial SAVED_64_HEX_TRIAL_ID
```

This calls a bounded, single Claude agent via API; it loads no local model and
launches no GPU job. The agent reads paged public trace messages and the actual
HTML source, then views the rendered PNG directly. It cannot finish without
inspecting every trace/source page and the screenshot. It cites training-only
preference IDs and known trace steps; unknown citations are rejected. Candidate
skills are run context, not authoritative preference evidence. Held-out labels,
old reward scores, and post-hoc human ratings are excluded from the input packet.

Every report saves exact inputs, model/prompt identity, input hashes, tool reads,
usage, observable findings, task fulfillment, correction handling, and limitations.
The verdict is `liked`, `disliked`, or `uncertain`, with **no calibrated percentage**.
It is not wired into either optimizer. Source/pixel provenance and static-desktop
limitations are explicit. Original Qwen samples are single-turn HTML generations;
this adapter does not invent tool calls, edits, or correction turns for them.
It does not yet connect arbitrary historical multi-step sessions to final artifacts.
The existing backend trace investigator remains a separate implementation.

This is a prototype check of the known failure, not an independent test set.
Getting that example right does not establish judge quality. New human-rated
outputs and both-label checks are still needed before comparing methods or
using the replacement as an optimization reward.

Method names and scores are visible in this journal. It is an unblinded progress
view; viewing final candidates here can compromise a later blinded preference
comparison. Use the separate blind gallery first when measuring blind choices.

`blind-gallery.html` shows pixels and task briefs without method names, scores,
or generated JavaScript. `reveal-key.json` stores the identities separately.
Have Henry record preferred candidates, ties, or neither before opening the
key. Keep all test tasks and unsuccessful candidates in the report. Classifier
reward is an optimization metric; the claimed ordering remains unproven until
the blinded human comparison supports it.

```sh
python -m pytest scripts/website_taste/tests --no-cov -q
```

Tests exercise source boundaries, provenance validation, grouped splits,
unreviewed-label gates, immutable experiment hashes, cached receipts, pinned
scoring, and the real GEPA library with tiny fake generation/score functions.
